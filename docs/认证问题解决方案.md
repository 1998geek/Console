# Swagger UI 认证问题解决方案

## 问题描述

登录成功后，访问 `/api/v1/auth/me` 接口返回 **403 Forbidden** 错误。

## 问题原因

您没有在 Swagger UI 中正确配置认证信息。**仅仅复制 token 到单个请求的 header 中是不够的**。

## 解决方案（重要！）

### 第1步：登录获取 Token

1. 在 Swagger UI 中找到 `POST /api/v1/auth/login` 接口
2. 点击 "Try it out"
3. 输入用户名和密码：
   ```json
   {
     "username": "admin",
     "password": "admin123"
   }
   ```
4. 点击 "Execute"
5. 从响应中**复制 `access_token`** 的值（一个很长的字符串，以 `eyJ` 开头）

### 第2步：使用 Authorize 按钮（关键步骤！）

⚠️ **这是最重要的一步！**

1. 在 Swagger UI 页面的**右上角**找到 **"Authorize"** 按钮（带有锁图标 🔓）
2. **点击 "Authorize" 按钮**
3. 在弹出的对话框中，找到 "Bearer (http, Bearer)" 部分
4. 在 "Value" 输入框中**粘贴您的 access token**
   - 可以直接粘贴 token：`eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...`
   - 或者带 Bearer 前缀：`Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...`
5. 点击 **"Authorize"** 按钮
6. 点击 **"Close"** 关闭对话框

### 第3步：测试接口

现在您可以成功调用需要认证的接口了：

1. 尝试 `GET /api/v1/auth/me`：
   - 点击 "Try it out"
   - 点击 "Execute"
   - 应该返回 **200 OK** 和您的用户信息

2. 尝试 `POST /api/v1/auth/logout`：
   - 点击 "Try it out"
   - 点击 "Execute"
   - 应该返回 **200 OK**

## 为什么必须这样做？

### ❌ 不起作用的方式：
- 手动在单个请求中添加 `Authorization` header
- 把 token 复制到请求体中
- 在没有点击 "Authorize" 按钮的情况下使用 token

### ✅ 正确的方式：
- 使用 Swagger UI **右上角的 "Authorize" 按钮**
- 这会配置 Swagger UI 自动在**所有请求**中添加 `Authorization: Bearer <token>` header

## 使用 curl 测试（替代方案）

如果您更喜欢命令行工具：

```bash
# 1. 登录获取 token
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "admin123"}'

# 2. 使用 token 访问接口
TOKEN="<您的access_token>"

curl -X GET http://localhost:8000/api/v1/auth/me \
  -H "Authorization: Bearer $TOKEN"

curl -X POST http://localhost:8000/api/v1/auth/logout \
  -H "Authorization: Bearer $TOKEN"
```

## 常见问题

### Q: 我点击了 Authorize 按钮，但还是返回 403？
**A:** 请确保您复制了完整的 token。token 非常长（200+ 字符），请确保没有遗漏任何部分。

### Q: Token 过期了怎么办？
**A:** Token 有效期为 24 小时。过期后需要重新登录获取新的 token。

### Q: 我应该使用 access_token 还是 refresh_token？
**A:** 使用 **access_token**。refresh_token 用于刷新 access_token，不能直接用于接口认证。

### Q: 锁图标有什么意义？
**A:** 
- 🔓 未授权状态
- 🔒 已授权状态

如果看到 🔒，说明您已经成功配置了认证。

## 技术细节

### JWT Token 结构

Access token 是一个 JWT（JSON Web Token），包含：
- `sub`：用户名
- `is_admin`：是否为管理员
- `exp`：过期时间
- `type`：token 类型（"access"）

### 认证流程

1. **登录**：用户名/密码换取 access_token + refresh_token
2. **认证**：请求时发送 `Authorization: Bearer <access_token>` header
3. **验证**：服务器解码 JWT，验证签名和过期时间
4. **授权**：服务器检查用户权限
